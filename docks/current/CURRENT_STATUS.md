# Current Status — Quantum Decoherence Predictor

## Цикл репликации закрыт (2026-09-20)

Очередь `docks/tasks/actual/` пуста. `pytest tests/` зелёный — **138 тестов**.

Предыдущий цикл (задачи 13–21) довёл обе статьи до сабмит-вида. Этот цикл
(задачи 22–25) проверил, что в них написано, — и **пять из шести спорных
выводов Paper 2 не пережили репликацию**. Ни одна таблица при этом не
изменилась: все опубликованные числа лежат внутри разброса повторных прогонов.
Рассыпались утверждения, надстроенные над таблицами.

### Что не пережило репликацию

| Утверждение | Итог |
|---|---|
| `physics_lstm` хуже `lstm_only` на XXZ (0.636 vs 0.673) | не разрешается: 0.599±0.120 против 0.633±0.060 |
| Оптимальный порог τ = 0.5 для XXZ | отозвано: размах по τ 0.068 < разброса между сидами 0.085 |
| `physics_lstm` деградирует при росте данных | опровергнуто: знак меняется по сидам (−0.263, +0.287, −0.192) |
| E11a меняет R² на AUROC | опровергнуто: окно 20 лучше по обеим метрикам во всех 6 сравнениях |
| Провал предсказуемости у J ≈ h | опровергнуто: минимум кочует по сидам (J=1.0, 2.0, 0.8) |
| TFIM-потолок структурен | **устояло** — теория предсказывала монотонный спад, он и наблюдается |

Общая причина у всех пяти: каждое опиралось на одиночный прогон, а разброс
между сидами в этом пайплайне доходит до ±0.36 по R². Два утверждения вдобавок
сравнивали конфигурации, отличавшиеся больше чем одним фактором (E11b против
E8c — ещё и окном, patience и inference-кодами; E11a против E7a — окном,
min-gap и протоколом оценки).

Устояли главные выводы: **Transformer — рекомендуемая архитектура** (лучший на
обоих сценариях с наименьшим разбросом: 0.843±0.028 на D, 0.699±0.045 на E) и
структурность TFIM-потолка.

### Воспроизводимость

Найдено и закрыто три дефекта:

1. Обучение не сеяло RNG фреймворка.
2. Симулятор брал начальное состояние из незасеянного глобального потока.
3. Экспериментальные скрипты строили обучающие команды сами и сид не передавали
   — то есть фикс на уровне use-case их не покрывал (11 мест, 6 из них
   backing статей).

Проверено двумя способами: повторный прогон e7 даёт побайтово идентичные CSV, и
R2 случайно посчитали два независимых процесса — 27 пересекающихся строк
совпали побитово.

**Оговорка:** побитовое совпадение держится **при одинаковом состоянии кеша
траекторий**. Начальные состояния берутся из одного засеянного потока, и
сколько его израсходуется, зависит от числа попаданий в кеш. Холодный кеш (с
него стартует внешний повторяющий) и полностью прогретый детерминированы,
частично прогретый — нет (замерено ~0.015 по R²). Убрать оговорку можно,
привязав содержимое траектории к ключу кеша, но это сменит RNG-поток и
обесценит все опубликованные числа.

Отдельно: прерванный прогон оставлял битую запись в кеше, и из-за
детерминированных ключей она отравляла все последующие прогоны. Запись теперь
идёт через временные файлы с переименованием, битая запись читается как промах.

### Утечки нет — проверено по трём осям

- **Сплит идёт по траекториям**, а не по окнам. Это главное: из одной
  траектории режется несколько окон с общим T₂.
- **Нормализация считается только по `train_idx`.**
- **Перекрытие конфигураций в E11a не завышает результат** (R4): ΔR² =
  −0.000±0.009 на XXZ и +0.015±0.059 на TFIM. Проверялось потому, что на XXZ
  конфигурация почти задаёт T₂ (разброс внутри 0.25–0.53 против 1.90 между).

### Как запустить

```bash
source .venv/bin/activate
python app.py          # http://localhost:7860 — макет аудита, 7 экранов
pytest tests/
make pdf               # обе статьи → paper/paper_1/main.pdf, paper/paper_2/paper2.pdf
make pdf-ru            # разбор на русском
```

Replay эксперимента: вкладка **02 Runs** → E8 → fast. Не запускать E6/E8 full
из UI — перезапишут чемпионские CSV. Пробы R1–R5 пишут только в свои CSV, это
закреплено тестом.
